# Taspa database schema

**PostgreSQL contract · 18 November 2026**

This is a logical schema for the first migrations. [Product rules](PRODUCT_SPEC.md) govern behavior. [API_SPEC.md](API_SPEC.md) defines the client contract and [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md) defines how data is consumed.

## Conventions and exposure

- Use a Supabase PostgreSQL version supporting invoker views and unique keys with nulls treated as equal. Use UUIDs for Taspa entities, bigint for TMDB IDs and row revisions, timestamptz for server instants, date for optional viewing days and date-only releases. Composite relationship keys below also define uniqueness. Server writes control ordering timestamps and revisions.
- Use one exposed `api` schema for curated direct relations and RPCs. Keep `private` tables and helpers outside the Data API exposed schemas. Supabase-managed `auth` and `storage` keep their usual boundaries. Revoke default object and function privileges. Grant only documented operations and columns to `anon` and `authenticated`. Enable RLS when each exposed table is created. Internal tables have no client table grants. For an exposed view, use invoker semantics with base grants and RLS, or a secured RPC projection when base grants would expose data. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) · [Supabase function security](https://supabase.com/docs/guides/database/functions)
- RPCs that access private relations use narrowly scoped definer roles, fixed empty search path, schema-qualified objects, explicit validation and least-required EXECUTE grants. Derive the actor from `auth.uid()`, check active account and authorization inside the transaction, and return only the prescribed projection. Privileged Edge calls receive a separate server-only grant path. Fail closed for unready/deleting accounts and hidden targets. Do not trust roles or audience in user-editable Auth metadata.
- Normal writes take desired state rather than toggles. Normalize empty optional fields at the boundary. Store watched dates with no default and validate a supplied day against the viewer's local current day using the validated account timezone, or a validated device timezone for owner-only logging. Client and SQL agree on this rule. Keep original calendar dates on later timezone changes.

## Catalog

Normalized public records are an intentional projection of permitted TMDB metadata. Locale-facing fields are stored for launch locales only. Unavailable or withdrawn records preserve references and owner history. Public views can omit unavailable descriptions/art while returning the minimum allowed title identity. Avoid public grants on raw/provider workflow data.

| Relation | Keys and significant fields | Invariants / indexes |
| --- | --- | --- |
| `api.titles` | PK `id`. `kind` movie/show, `tmdb_id`, `display_title`, `original_title`, `original_language`, `overview`, poster and backdrop paths, first release day, runtime minutes, source release status, `catalog_state`, `catalog_revision`, `updated_at`. | Unique `(kind, tmdb_id)`, `(id, kind)`. Index public rows by `(kind, first_release_day, id)` when needed for date browse. |
| `api.seasons` | PK `id`. `show_id`, constrained show kind, `tmdb_id`, `season_number`, title, art, first known release day, `release_finished`, `coverage`, `is_special`, `available`. | FK `(show_id, kind)` forces show. Unique `tmdb_id`, `(id, show_id)`. Index `(show_id, season_number, id)`. At most one available season per number within a show. |
| `api.episodes` | PK `id`. `season_id`, `show_id`, `tmdb_id`, episode number/title, runtime, air day/instant and release evidence, `is_released`, `available`. | Composite FK `(season_id, show_id)`. Unique `tmdb_id` and `(id, show_id)`. Index `(season_id, episode_number, id)` and released available rows by `(show_id, season_id, episode_number, id)`. Unique available numbering per season. | `private.catalog_metadata` | Title-scoped normalized aliases/localizations, genres and supporting metadata, trailers, similar IDs, and coverage flags; optional episode synopsis keyed by episode identity in `private.episode_details`. | Prefer bounded JSON for display-only arrays and scalar keys for queryable attributes. Index any launch filtering attributes only as used. Summaries select requester locale with catalog fallback. |
| `private.title_releases` | PK `(title_id, market, release_kind)`, release day/instant, confidence, source timezone where known, source checked time. | Index `(market, release_day, title_id)` for reminders. Record semantics such as theatrical or digital release. A regional reminder uses the configured eligible kind and verified date. |
| `private.catalog_cache`, `private.catalog_refresh` | Cache by normalized request hash and version, with value, stale/expiry and lease. Refresh by title, with due time, attempts and lease. | Index refresh `(due_at, title_id)`. Cap eviction/retention. Track provider budgets through bounded counters in `private.rate_limits`. |

Determine availability from confirmed release evidence and stable metadata. Use timestamp only with trustworthy source timing; a date-only episode becomes eligible conservatively after its source day ends when the source timezone is known, or from confirmation if its timing cannot be resolved. Do not interpret an unknown date as released for TV. New releases and corrections advance the catalog revision. An incomplete import is not a complete replacement. Reorder/retire records in one import transaction with staging that avoids transient unique-number collisions. Genre browsing can use the allowlisted TMDB discovery category and normalized cached results without requiring a separate genre index on day one.

| Relation | Keys and significant fields | Invariants / indexes |
| --- | --- | --- |
| `api.profiles` | PK `user_id` FK to Auth user; canonical lowercase unique `handle`, display name, and minimal identity. | Unique normalized handle. Bound length/characters and reserved names. RLS checks active state and blocks. Full bio and audience choices are private. Profile writes grant only allowed personal fields. |
| `private.profile_settings` | PK `user_id` FK to profile; lifecycle ready/deleting, profile visibility, library audience, tracking activity opt-in, timezone and explicit market, bio, avatar object key, and deletion timestamps as needed. | Default library Only me, tracking activity off. Market timezone defaults apply only when legitimately established. Avatar path is owned by account. |
| `private.wanted_entries` | PK `(user_id, title_id)`; nullable `added_at` means inactive when null, `revision`. | One entry per title per user across media. | `private.movie_viewings` | PK `id` from caller-generated viewing UUID; `user_id`, `movie_id`, optional `watched_on`, `logged_at`, optional `deleted_at`, `revision`. | Composite catalog FK forces movie kind. Scrub the date when deleted; retain preimage only in bounded Undo. |
| `private.tracked_shows` | PK `(user_id, show_id)`; intent Watching/On Hold/Dropped or null for removed, `last_activity_at`, `revision`. | Composite FK forces show kind. Index active `(user_id, intent, last_activity_at DESC, show_id)` and `(show_id, user_id)`. Completed is derived only on a Watching intent. |
| `private.episode_marks` | PK `(user_id, episode_id)`; `show_id`, `watched`, optional `watched_on`, `revision`. | Composite FKs match tracked owner/show and episode/show. Unwatched requires null date. Index watched `(user_id, show_id, episode_id)`. A tracking transaction clears watched marks and dates when removing tracking. Unwatched tombstones preserve revision history. |
| `private.ratings` | Logical key `(user_id, title_id, season_id)` where null season means movie/show. Stable ID, half-star integer units 1–10 or null for cleared, audience and revision. | Unique with nulls treated as equal. Composite FK `(season_id, title_id)` to season/show. Index eligible public ratings by target with user key. |
| `private.reviews` | Same unique logical target and composite FK, stable slot ID and monotonically increasing revision. Optional unique public `discussion_id`, bounded body, spoiler flag, audience, publication state/time, moderation state. | Clearing retires the discussion and its interactions atomically and keeps the slot revision. | `private.tracking_operations` | PK `(user_id, operation_id)`, title, validated request hash, compact result revision references, operation time, temporary before/after receipt data for Undo, optional undo relationship. | Unique original-to-successful-undo reference. Receipt data never returned to another user. Keep enough to retry without creating another viewing. Index expiry for batch cleanup. |

### Tracking transaction and derived progress

Serialize all tracking changes for one user and title with the same transaction-scoped advisory lock on the pair. Hash collisions only serialize unrelated requests. Lock the title in shared mode for tracking and exclusively for catalog publication; use a fixed order (title, user/title lock, rows). Read eligibility again in the transaction. Use revision 0 for a never-written record and persistent versions on tombstones so write/unwrite cannot look like an untouched row. Check the affected revisions, not a global account version. Every mutator including Undo goes through the same path. Use SQL constraints/FKs for kind, identity and relationships, and this single write boundary for cross-table exclusivity.

First watch creates a single viewing and deactivates Wanted atomically. Log rewatch is a separate explicit intent. Deleting the last viewing leaves the title untracked. Starting a show requires a released regular episode and removes Wanted at zero progress. First valid episode or batch may also start the show. Hold/drop persists across individual edits and catalog imports. Use a batch confirmation preview for bulk operations, capturing scope, range, catalog revision, affected identifiers and revisions. Recompute legal scope and compare the observed snapshot before applying. Never overwrite prior dates when filling gaps. Mark season unwatched resets all saved watches in that regular season, including retained corrected entries. Cap batch size to a documented supported maximum and reject with an actionable error before changes if outside it. Establish the cap from catalog samples before release, with no silent partial tracking.

Generate shared read projections in SQL once. A title row is Watched if it has an active movie viewing. Show progress uses only released, available regular episodes. Season count includes a season after its first release. Season completion requires reliable release-finished and all released regular episodes watched, with coverage sufficient to make the claim. For the show, use eligible release and coverage checks, end/cancel evidence, and absence of known future regular episodes for Completed. Caught up is a display state, not stored intent. Choose earliest released regular gap by season, episode then ID. Use separately tracked specials and retained watches on unavailable entries in history. Published show/season data and user tracking snapshots only expose counts/dates appropriate to their audience. Compute Continue Watching from the same next-gap projection used by show details and retain filters/sort across both groups.

Compute profile movie, show and episode totals from active tracking data with the owner's visibility. Count a movie once regardless of rewatch count. Count a show after its first currently watched episode and count each currently watched episode once, including specials and saved watches needing catalog repair. These lifetime counts have a different scope from regular season/show progress. Undated watches still count. Viewer-facing totals and rows never include individual viewing dates.

Use server-side receipt deduplication before processing. A repeated operation UUID with a different canonical payload is invalid. Same payload returns current authorized result references linked to the original execution without reapplying it. Include first-submission client timestamp and refuse previously unseen operations older than 30 days. Retain receipt IDs/hash for at least 35 days and reject overly future timestamps. Retain Undo preimages for 24 hours from commit, then delete the sensitive preimage. For an expired queued operation show current state and ask the user to reapply. A reapply is a fresh explicit operation. Restore the rows whose versions match the receipt. Treat interdependent changes, such as first watch plus Wanted removal, as one restore unit when necessary to preserve exclusivity. Return any remaining partial outcome. Never write directly from Flutter into tracked tables.

## Social, safety and notifications

| Relation | Keys and significant fields | Invariants / indexes |
| --- | --- | --- |
| `private.follows` | PK `(follower_id, followed_id)`; pending/accepted, requested/accepted time. | No self-follow. Index `(followed_id, state, follower_id)`. Use one lock order across both actors for follow, block and interacting writes as needed. |
| `private.blocks` | PK `(blocker_id, blocked_id)`; created time. | No self-block. Reverse index for either-direction checks. Blocking drops both follow/request directions. |
| `private.review_likes` | PK `(review_id, user_id)`; FK from review ID to current discussion ID, created time. | One current like, no audience override. Count only reader-eligible interactions on visible reviews. |
| `private.review_comments` | PK ID, FK to current discussion ID and author FK, body, spoiler flag, created/edited time, optional hidden/deleted state and revision. | Index visible thread `(review_id, created_at, id)`. Review owner can hide. Author can edit/delete. Surviving signed-in blocked pairs do not see each other's contributions. |
| `private.activity` | PK ID; actor, event kind, title/season, optional review or rating target, created time, event audience cap, unique source key. | Index `(actor_id, created_at DESC, id DESC)`. One source event for current published review, explicitly shared rating, or first opted-in milestone. Edits update event projection through the current source. Bulk writes produce at most one milestone. |
| `private.reports` | PK ID; reporter, typed resolvable target at report time, reason, bounded optional comment, state and times. | Prevent unauthorized target reports and throttle duplicates. Index open queue by `(created_at, id)`. Moderation through restricted operations. |
| `private.notification_preferences` | PK `(user_id, category)`; inbox and push flags. | Defaults from the product, with social push off and release push opt-in. |
| `private.notifications` | PK ID; recipient, kind, subject/group key, event time, read and suppression timestamps. | Unique `(recipient, kind, group_key)`. Index `(recipient, event_at DESC, id DESC)`. Grouped entries derive eligible contributors live. Mark grouped events unread only on a new eligible action. |
| `private.device_tokens` | PK installation ID; owner, token, platform, installation credential verifier, binding revision, last seen, lease expiry, disabled time. | Unique active token across installations. Index active `(owner, lease_expiry)`. Server manages ownership, expiry, and invalidation. Token body and verifier never selected by clients. |
| `private.push_deliveries` | PK `(notification_id, installation_id, generation)`; token binding version, due/lease, attempts, terminal status, optional provider result code. | Index queued `(due_at, notification_id)`. Generation only advances on an eligible new event. Revalidate notification, preference, and binding before send. |
| `private.release_events`, `private.account_deletion_jobs` | Release events keyed by stable title/episode identity and event kind, with evidence, progress cursor for fan-out and schedule. Deletion jobs keyed by user, with due time, attempts and cleanup stage. | Unique stable actual episode event. Wanted reminder key uses title, market, release kind and intended date, with send-time suppression of older date. Index pending work. Catalog corrections must not repeat emitted release events. Jobs are service-only. |

FKs to profiles cascade for user-owned library/social/session data where appropriate. Delete review interactions when the review's public identity is retired, or keep only moderation data according to approved retention. Account cleanup jobs must survive Auth deletion until acknowledged. At account delete, tombstone first, then remove private objects and active data. Decide the reports, backups and operational retention policy before production. Catalog FK targets are retired in place while referenced.

Catalog publication creates one event per newly confirmed regular episode, deduped by stable ID. Fan-out re-evaluates each owner's effective status after the catalog update so a returning Completed show can qualify. Keep same-day episode drops grouped by show and the recipient's local release day. Skip retroactive notifications for previously released episodes discovered during initial import or metadata repair. Use follow relationship/request identity and review/discussion identity for social dedupe. Suppress self-events. Mark milestone eligibility on the first tracking transition even if activity was off, so removing and re-adding a title cannot retroactively publish that milestone. Existing inactive tracking/history tombstones can carry that fact, with only the minimum data retained.

## RLS and visibility

| Surface | Who can read | Who can change |
| --- | --- | --- |
| Public catalog rows | Guests and approved sessions, catalog visibility only | Server import procedures only. Provider evidence and raw cache remain private. |
| Profile identity | Owner and guests/authenticated according to minimal identity and block rules | Ready owner can update allowed display fields only. Handle claim and lifecycle require RPC/Edge. Guests see no private bio, counts or library dates. |
| Profile detail, follower lists, library, progress | Owner, or audience-filtered projection. First apply active/deleting/block gates. Private profile caps broad access at approved followers. | Owner RPCs and narrowly scoped display-field update only. History, receipt and dates are always owner-only. |
| Ratings and reviews | Independently authorized by each content audience. Public may reach guests. Reader-blocked authors are excluded. Rating may remain visible when text is concealed. | Owner sets each independently. Server moderates removals. Only eligible public ratings on active public profiles enter global aggregation. Expose count and average only per product threshold behavior. |
| Activity, likes, comments | Feed only for accepted follows and current authorized content. Comments and likes respect review visibility, profile settings, moderation and blocks. Protected thread/text gates use explicit reveal context. | Authenticated actor under social RPC, with target recheck. Review owner can hide a comment. |
| Inbox, preferences, devices, operations, reports | Inbox and preferences owner projection; current authorization applies to each notification. Device secrets, operation internals and report queues server-only. A reporter may read only their permitted outcome. | Owner through scoped RPC. Server creates events, receipts, delivery rows and moderates. |
| Storage | Private avatars bucket. Client roles cannot directly read, list, sign or mutate objects. Authorized avatar Edge read checks current profile access per request. | Avatar Edge validates active owner and input, stages replacement, swaps authorized pointer and cleans old asset. |

Initialize audience to Only me for library and opinions. Evaluate audience as owner, accepted follower or permitted public viewer, with both-way blocking first for signed-in readers. Track account visibility in database state instead of stale JWT claims. Tighten profile to private in one transaction that downgrades existing Public library, opinion and activity allowances to Followers. A new opinion published under private mode stores at most Followers. Switching to public changes the profile shell only. Explicit audience edits are required to reopen previously capped entries. Re-evaluate joins and event eligibility on read/send, including pointers opened from external previews. Access revocation also affects counts and profiles. Likes or notification rows are not a source of authority for review access.

Serialize audience changes and publication against the subject's profile-settings row. Multi-actor relationship writes use sorted actor IDs for their locks. Place authorization checks after the relevant write locks and use the same lock order in functions that combine these actions. Feed and inbox reads evaluate current access, including after a concurrent change. Push is neutral because network dispatch and later revocation cannot share an atomic transaction.

Search and public previews use the same checked projections. Do not expose unmasked review bodies through raw SELECT, Storage, server search projections, or Realtime. Incomplete season review text and flagged review text appear only after explicit view request with reveal intent and current authorization. Store no protected teaser in push. Keep all keyset ordering terms indexed on hot paths. Begin with database query plans and observed slow queries before adding rating aggregate materialization, precomputed feed fan-out, or additional search extensions.
